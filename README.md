# ROI 预估工具

一个完全在浏览器本地运行的 ROI 预测工作台，用历史投放批次拟合长期 ROI 曲线、预估新批次结果，并反推早期考核标准。

应用没有后端，计算、草稿和模型包默认保存在当前浏览器。它适合辅助投放分析和目标讨论，不构成财务、审计或收益保证。

## 功能概览

应用包含三个工作区：

- **预估曲线拟合**：联合拟合一个或多个同模式历史批次，比较候选模型并保存完整模型包。
- **ROI 预估**：使用模型包和新批次的真实观测，预测目标日 ROI、目标差距和首次达标日。
- **考核标准反推**：从目标 ROI 和目标周期反推 D1 ROI、D7 ROI；使用 ROI + 留存率模型包时，还会联合反推次留和 7 留。

当前数据、项目文档和模型包格式为 **V4**。

## 指标口径

- `ROI = 累计收入 / 累计成本`。
- ROI 和 LTV 都按累计值录入，随观测日增加不能下降。
- LTV + CAC 模式逐行换算：`ROI(Dn) = 累计 LTV(Dn) / CAC(Dn)`；每个观测日都必须提供大于 0 的 CAC。
- “次留”指次日留存率，“7 留”指第 7 日留存率。
- 默认目标是 ROI `1.37`、目标周期 D360，均可在页面修改。
- 回本或达标日是预测曲线首次达到当前目标 ROI 的日期；ROI 1.0 不会替代用户设置的目标。

## 启动

需要 Node.js 20+ 和 pnpm 10+：

```bash
pnpm install
pnpm dev --host 127.0.0.1
```

浏览器打开终端显示的地址，通常为 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)。如果端口被占用，Vite 会选择其他端口，以终端输出为准。

常用命令：

```bash
pnpm test:run
pnpm build
pnpm test:e2e
pnpm exec vite preview --host 127.0.0.1
```

`pnpm build` 会生成 `dist` 静态文件；应用不依赖 API 或数据库，可部署到普通静态文件服务。

## 使用流程

### 1. 拟合并保存模型包

1. 选择统一输入模式：ROI、ROI + 留存率或 LTV + CAC。
2. 手工添加历史批次，或导入包含多个批次的 CSV。同一次拟合不能混用不同输入模式。
3. 为每个批次录入 D1–D360 内不重复的真实观测日；所有批次校验通过后才能联合拟合。
4. 点击“开始拟合”，查看批次综合曲线、各模型曲线、样本内误差、回测证据和模型资格。
5. 输入模型包名称并保存。至少一个模型有效时可以保存；无效模型及原因也会保留在模型包中。同名模型包保存为不同时间版本，不会覆盖。

普通 ROI 与 LTV + CAC 模式主要使用历史倍率、对数、幂函数和饱和模型。历史倍率模型至少需要 3 个带真实 D360 的成熟历史批次，并在回测时排除被预测批次。

ROI + 留存率模式按观测日同时录入累计 ROI 和对应留存率，可使用留存倍率、留存参数模型及单调样条模型。模型是否参与综合取决于样本量、曲线安全性和回测资格；留存率与长期 ROI 的统计关联不代表因果关系。

多批次拟合中的历史批次等权。获得资格的有效模型逐日等权形成综合曲线。

### 2. 预估新批次 ROI

1. 选择一个已保存的模型包；输入模式由模型包决定。
2. 输入新批次的一个或多个真实观测日，或导入 CSV。预估页只使用导入文件中的第一个批次。
3. 设置目标 ROI 和目标周期。
4. 点击“开始预估”。

每个有效模型使用新批次的全部观测点校准，越新的观测日权重越高。综合曲线是有效模型的逐日等权平均；图表阴影表示各模型预测的最小值至最大值，是模型分歧范围，不是统计置信区间。

如果真实观测已经达到目标，首次达标日优先采用真实观测结果。只有首次达标日不晚于目标周期，才判定目标周期内达成。

ROI + 留存率模型包要求新批次至少有 2 个同时包含 ROI 和对应留存率的观测点。

### 3. 反推考核标准

1. 选择模型包，输入目标 ROI 和 D7–D360 的目标周期。
2. 点击“开始反推”。
3. 查看 ROI 模型基准、最终推荐值、误差范围和风险提示。

普通 ROI 模型包只反推 D1 ROI、D7 ROI。系统按每个有效模型分别反算并做回测误差折损，再等权汇总。

ROI + 留存率模型包要求至少 3 个同时具备 D1、D7、D360 ROI 及 D1、D7 留存率的完整成熟批次。系统将 D1 ROI、D7 ROI、次留和 7 留作为一个不可拆分的四维组合，输出 ROI 优先型、均衡型（默认推荐）和留存优先型。

每一行必须作为完整组合使用，不能跨方案拼接四项指标。页面目前把目标日结果标为“保守下界”；从实际算法看，它是各有效模型经误差折损后的等权平均，本文称为“保守综合值”。它不是所有模型预测的数学最小值，也不保证每个模型都单独达到目标。

当目标超出成熟 D360 历史范围时，系统会按目标与历史边界的比例扩展 D1/D7 ROI 搜索区间，并在 `0%–100%` 内联合搜索次留和 7 留。求解采用粗网格、多起点数值优化、离散取整和最终复验，属于高覆盖率近似结果，不保证连续四维空间的全局最优。

置信度主要由完整成熟样本数量划分：

- 3–4 个：低置信度试算，不建议直接作为正式考核标准；
- 5–9 个：中置信度试算；
- 10 个及以上：高置信度。

该分级不等于因果可信度，也不会自动因历史范围外外推而降级。超出历史范围或出现不现实的留存标准时，应结合业务经验人工复核。

## CSV 导入

拟合页和 ROI 预估页均支持 CSV：拟合页读取全部有效批次，预估页只使用第一个批次。

通用列：

- `batch`：批次名称，也接受 `cohort_name`；同一文件内必须唯一。
- `mode`：`roi`、`roi_retention` 或 `ltv_cac`。
- `spend`：可选的批次投放成本；当前联合拟合按批次等权，不使用该字段加权。

ROI 模式使用 `roi_天数`：

```csv
batch,mode,roi_1,roi_7,roi_30,roi_360
历史批次 A,roi,0.10,0.24,0.48,1.42
历史批次 B,roi,0.11,0.26,0.51,1.50
```

ROI + 留存率模式使用逐点成对列 `roi_天数,retention_天数`。考核标准反推至少需要 D1、D7 和 D360 ROI，其中 D1、D7 必须有对应留存率：

```csv
batch,mode,roi_1,retention_1,roi_7,retention_7,roi_360
留存批次 A,roi_retention,0.10,28%,0.24,15%,1.42
```

旧字段 `next_day_retention,day_7_retention` 仍可兼容读取，并分别映射到 D1、D7。新文件建议使用逐点 `retention_天数`。

LTV + CAC 模式必须为每个观测日成对提供 `ltv_天数,cac_天数`：

```csv
batch,mode,ltv_1,cac_1,ltv_7,cac_7,ltv_30,cac_30
历史 LTV 批次,ltv_cac,2,20,6,24,12,30
```

百分比可写成 `22%`；裸数字 `0.22` 按数值本身解析。下降的源累计值默认阻止导入，只有用户明确选择修复时才按累计最大值修正。LTV/CAC 换算后的 ROI 下降不会自动修复，必须修改原数据。旧版批次级 `cac` 列不再支持。

页面可以直接下载三种当前格式的 CSV 模板。

## 本地保存与项目文档

- 历史输入草稿和模型包保存在浏览器 `localStorage`，刷新后可恢复。
- ROI 预估输入、目标和结果是临时状态，不写入项目文档。
- “导出数据到本地”生成 `.roi.json` 文件，包含有效历史输入和全部 V4 模型包。
- “从本地导入数据”会校验文件格式并替换当前项目数据和模型包。
- V3 项目草稿可以迁移到 V4；V3 模型包会显示为不兼容，需要重新拟合。更旧的批次级 CAC 数据不会自动迁移。
- 清理站点数据、使用隐私模式、换浏览器或换设备都可能导致本地缓存丢失。重要数据应定期导出备份。

导入项目文档目前不是事务操作：模型包和项目草稿分两步写入浏览器缓存。极少数情况下，如果第二步写入失败，模型包可能已经变化。因此导入前应先导出当前数据备份，并在导入后检查模型包和批次数量。

## 模型解释边界

- 综合曲线采用等权平均，不代表统计意义上的最优集成。
- 模型分歧范围不是置信区间。
- 回测误差折损属于工程上的保守修正，不构成概率保证。
- 留存增强模型基于历史相关性，不能据此认定提高留存必然带来长期 ROI 增长。
- 历史范围外结果属于外推，风险高于历史范围内反推。
- 样本少、指标共线或候选方案差异小时，联合达标边界可能缺乏区分度；页面仍展示组合并给出提示。

## 当前已知问题

截至 2026-09-09：

- 全量 Vitest 为 **269/274 通过，5 个失败**。失败涉及对数模型首点锚定、饱和模型常量边界、稀疏样本模型选择，以及 2 个已落后于当前交互的组件测试。
- 四维考核标准相关定向测试通过，但一次完整反推可能需要数秒；扩大搜索密度会显著增加计算量。
- “保守综合值”允许平均值达标但个别模型不达标。区分度或逐模型一致性不足时，页面只提示风险，不隐藏方案。
- 留存率按 `0%–100%` 搜索，可能产生数学可行但业务不现实的组合。
- 外推结果的置信度不会自动降级。
- 项目文档导入失败时不能严格保证原数据完全不变。
- Playwright 端到端测试需要本机已安装可用的浏览器；Vitest 或构建通过不能替代浏览器连通性和完整交互验证。
